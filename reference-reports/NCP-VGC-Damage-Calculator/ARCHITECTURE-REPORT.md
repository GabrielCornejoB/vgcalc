# Architecture Report — NCP-VGC-Damage-Calculator

## Overview
- Static, client-side, multi-page jQuery app with no build step, package manager, server, tests, or bundler. Each `*.html` entry point composes its own app by `<script>`-including a shared engine plus selected data files (`index.html:853-894`, `za-calc.html:697-720`, `lgpe-calc.html:757-778`).
- The "backend" is a set of global JS tables (`POKEDEX_*`, `MOVES_*`, `TYPE_CHART_*`, `ITEMS_*`, `ABILITIES_*`, `SETDEX_*`) plus per-generation damage functions; the "frontend" is two mirrored `poke-info` DOM panels (`#p1`/`#p2`), a `field-info` panel, and a result group, all in `index.html:119-835`.
- All mutable app state lives in two places: the DOM itself (inputs/selects/checkboxes are the source of truth, snapshotted per calc) and a handful of globals (`gen`, `pokedex`, `moves`, `typeChart`, `abilities`, `items`, `STATS`, `calculateAllMoves`, `damageResults` in `script_res/ap_calc.js:1728,2200`).
- Generation switching re-wires the entire app at runtime: one `$(".gen").change` handler swaps data tables, stat formulas, calc entry points, visible DOM (`gen-specific` classes), and the active setdex (`script_res/ap_calc.js:2202-2440`).
- Damage math is organized as a dispatcher + per-gen strategies: `GET_DAMAGE_HANDLER` (`script_res/damage_MASTER.js:4-25`) routes to `CALCULATE_DAMAGE_RBY/GSC/...`, `GET_DAMAGE_XY`, or `GET_DAMAGE_SV`; modern gens (7/8/9/10) all funnel into `CALCULATE_ALL_MOVES_SV` / `GET_DAMAGE_SV` (`script_res/damage_SV.js:6-192`).

## Data flow
- Flow 1: Any-input → full recalculation → rendered result. Any `.calc-trigger` change/keyup calls `calculate()` (`script_res/ap_calc.js:2666`); `calculate()` snapshots `new Pokemon($("#p1"))`, `new Pokemon($("#p2"))`, `new Field()` (`script_res/ap_calc.js:1732-1734`, constructors at `1927`, `2092`, move snapshot at `2070`), runs `damageResults = calculateAllMoves(p1, p2, field)` (`1735`), formats min/max % per move and per-side KO text via `getKOChanceText(..., field.getSide(i), ...)` (`1740-1781`, `script_res/ko_chance.js:1`), then the checked `.result-move` radio renders `#mainResult`/`#damageValues` (`script_res/ap_calc.js:1795-1871`). `calcQueue` guard (`1730`, `2653-2658`) coalesces cascading change events.
- Flow 2: Generation switch re-targets the whole calculator. `$(".gen").change` sets global `gen` and swaps `pokedex/typeChart/moves/items/abilities/STATS/calculateAllMoves/calcHP/calcStat` per case (`script_res/ap_calc.js:2202-2344`; e.g. gen 10 → `POKEDEX_CHAMPIONS` + `CALC_HP_CHAMP/CALC_STAT_CHAMP` at `2334-2343`), then `clearField()`, toggles `.gen-specific.g<gen>` visibility (`2350-2351`), rebuilds `CURRENT_SETDEX` via `loadSetdexScript()` (`2352`, `script_res/setdex_dynamic.js:5-27`), repopulates type/move/ability/item `<select>`s (`2386-2403`), and reloads sidebars (`2407-2409`). Natdex variants branch on `localStorage.dex` inside cases 8/9/10 (`2302`, `2313`, `2335`); `getGen()` (`2606-2618`) restores the persisted gen at boot (`2664`).
- Flow 3: Set selection → panel population → stats → recalc. `$(".set-selector").change` (`script_res/ap_calc.js:1164-1250`) looks up `setdex[species][setName]`, writes nature/ability/item/moves/EVs-or-SPs into panel fields and fires `.change()` on each (cascading into Flow 1); stat fields have dedicated `keyup/change` handlers that call `calcHP/calcStat` (function pointers set by Flow 2) plus `calcStats/calcEvTotal/calcStatPointTotal` (`script_res/ap_calc.js:189-305`), updating `.total`/`.max-hp`/HP bar before `calculate()` reads those `.total` texts as `rawStats/maxHP` (`1927-2035`).
- Flow 4: Modern damage pipeline (gens 7–10) + KO text. `CALCULATE_ALL_MOVES_SV` first mutates attacker/defender in place through ~20 `check*` hooks (Trace, Neutralizing Gas, Forecast, Terastal, Paradox abilities, Intimidate, Download, …) and finalizes boosted stats/speed (`script_res/damage_SV.js:6-54`), then loops 4×2 `GET_DAMAGE_SV` calls returning `{damage: [...16 rolls or per-hit arrays...], description}` (`60-70`, `72+`; shared helpers like `basePowerFunc`/`calcBPMods` in `script_res/damage_MASTER.js:1304,1568`). ## Patterns & rationale
- Pattern: `<script>`-tag dependency injection / page-level composition — why this way / trade-offs. Each HTML page declares exactly the data+engine files it needs, so LGPE/Z-A pages reuse `ap_calc.js` with tiny `COMPONENTS` maps (`setdex_dynamic-lgpe-za.js`) and only the damage files they need instead of a router or bundler. Trade-off: script order is load-bearing, globals collide silently (`COMPONENTS` is redefined per context), and dead/archived files (`legacy_scripts/`, `digidex` refs in `digicalc.html:434-442` pointing at files no longer present) linger.
- Pattern: Global registry + Strategy dispatch for generations — why this way / trade-offs. One mutable set of names (`gen`, `pokedex`, `moves`, `calculateAllMoves`, `calcHP/Stat`) lets all downstream code stay gen-agnostic, and adding a ruleset is mostly "add data globals + a case + a damage file" (gen 10/Champions followed exactly this path with `CALC_HP/STAT_CHAMP` and `POKEDEX/MOVES_CHAMPIONS`). Trade-off: hidden coupling — any file can read/mutate globals, and modern gens over-share one strategy (`GET_DAMAGE_SV` covers 7/8/9/10/ZA) so its `check*` preamble keeps accreting conditionals.
- Pattern: Data-as-code JS globals instead of JSON/fetch — why this way / trade-offs. Zero async loading, works from `file://`, trivial to hand-edit sets; merges via `$.extend` (`setdex_dynamic.js:22`, `move_data_za.js` overlay) are simple. Trade-off: ~16k-line `pokedex.js`, ~6k-line `move_data.js`, duplicated NATDEX tables, and no schema validation — shape drift only surfaces at runtime.
- Pattern: DOM-as-state with snapshot constructors — why this way / trade-offs. `Pokemon`/`Field` read the live panels on every calc, so there is no stale-model bug class and every widget automatically participates by adding the right CSS class. Trade-off: the HTML class contract is the API (rename a class and calc silently breaks), and per-keystroke full recalc + DOM reads is the performance ceiling.
- Pattern: Event-coalescing + progressive disclosure via CSS classes — why this way / trade-offs. `calcQueue` (`ap_calc.js:14-15,1730`) plus `gen-specific`/`natdex-specific` show/hide in the gen switch keeps one HTML file serving 10+ rulesets without re-rendering. Trade-off: visibility logic is split between markup classes and JS toggles (`2350-2384`, `switch_mode.js`), easy to leave a control visible in the wrong gen.
- Deliberate non-pattern: no modules, no state store, no tests/lint/CI — rationale is contributor friction for a community-maintained calculator (edit a setdex file, open the HTML file, done). Trade-off: regressions are caught by users; `debug.log` and `index.sublime-workspace` show the workflow is manual browser testing.

## Coupling & extension points
- Global-name coupling: `gen`, `pokedex`, `moves`, `typeChart`, `abilities`, `items`, `STATS`, `calculateAllMoves`, `calcHP/calcStat`, `setdex`, `CURRENT_SETDEX`, `COMPONENTS`, `ALL_SETDEX_CUSTOM`, `mechanicsTests/isCustomMods` — reimplementation should replace these with an explicit context object passed to calc functions.
- DOM class-name contract: `.calc-trigger` (recalc), `.terrain-trigger` (`getTerrainEffects`), `.poke-info .set-selector/.type1/.tera-type/.level/.base/.evs/.ivs/.sps/.boost/.nature/.ability/.item/.status/.move1..4 .move-*`, `.gen-specific.g<gen>`, `#p1/#p2` result locations (`resultLocations:1544`). New controls must carry these classes or wire manually.
- Script-load-order coupling: jQuery → `switch_mode.js` → data/setdex files → `setdex_dynamic*.js` → `ap_calc.js` → `damage_MASTER.js` → per-gen damage files → `ko_chance.js` → `statuscalc.js` → AFD → `sidebars.js` (`index.html:853-894`). Moving `ap_calc.js` earlier breaks gen init; moving damage files after consumers breaks dispatch.
- Setdex shape extension point: `{Species: {SetName: {sps|evs, nature, ability, item, moves[], ...}}}` merged in order with later sources winning (`setdex_dynamic.js:16-25`); to add a metagame, append its `SETDEX_*` to `COMPONENTS[gen]` in `setdex_dynamic-main.js` (or the lgpe-za variant) and include the script tag.
- Damage extension points: new modifier → add a `check*` call in `CALCULATE_ALL_MOVES_SV` (`damage_SV.js:6-54`) + handling inside `GET_DAMAGE_SV`/helpers; new move flag → extend the `MOVES_*` entry shape (cf. `cooldown`, `hitRange`, `plusEffects` in `move_data_za.js`) and the corresponding branch in `basePowerFunc/calcBPMods`; new EOT/hazard → extend `getAllEndOfTurnEffects` + `END_TURN_ORDER_*` (`ko_chance.js:466,742-744`).
- Persistence coupling: `localStorage` keys `theme`, `dex`, `gen`, `level`, `isAFD`, `g<gen>_sidebars`, per-set custom storage in `setdex_custom.js` — clearing cookies/localStorage is the documented fix when the UI desyncs (`index.html:114`).
