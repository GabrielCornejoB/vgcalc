# Architecture Report — ps

## Overview
- `pkmn/ps` monorepo of decoupled `@pkmn/*` libraries extracted from Pokémon Showdown, not a single app: static data (`dex`, `data`), wire protocol (`protocol`), client-side battle state (`client`), presentation/choices (`view`), team serialization (`sets`), team generation (`randoms`), format overrides (`mods`), vendored engine (`sim`, `streams`), auth (`login`), sprites (`img`), shared vocab (`types`) (`package.json:24-39`, `EXPLORER-REPORT.md:3-38`).
- Dependency direction is inward toward contracts: `types` → `dex` → `data` → `client`/`view`; `protocol` is the wire contract consumed by both `client` (`client/src/battle.ts:1-12`) and `view` (`view/src/formatter.ts:1-20`, `view/src/choices.ts:1-4`); `sim`/`randoms` sit sideways depending on `dex`/`streams`/`sets` (`randoms/src/index.ts:1-9`, `sim/package.json:34-38`).
- Two code origins coexist: hand-written libraries (`dex/index.ts`, `data/index.ts`, `protocol/src/index.ts`, `client/src/*`, `sets/src/*`, `view/src/*`, `login/index.ts`, `streams/index.ts`) vs. generated extractions from `vendor/` submodules via `./build` and `./import` (`build:1-179`, `sim/package.json:42-50`). `vendor/` is currently empty, so generated `sim`/`dex/data` JSON cannot be refreshed without submodule checkout (`EXPLORER-REPORT.md:49`).
- Build is per-package `tsc` dual CJS/ESM plus `tsup`/`esbuild` IIFE for browser globals (`window.pkmn.*`); `dex` additionally bundles `learnsets.json` separately (`build:31-179`).

## Data flow
- Flow 1: server battle line → client state (`protocol/src/index.ts:2003-2025` → `client/src/battle.ts:96-104` → `client/src/handler.ts:179-254` → `client/src/pokemon.ts:298-323` / `client/src/side.ts:208-289`). `parseBattleLine` strips trailing `[from]/[of]/[still]` kwargs and `upgradeBattleArgs` normalizes legacy forms; `Battle.add` keys on `|cmd|` and invokes the same-named `Handler` method; the handler resolves `PokemonIdent` (`parsePokemonId`/`getPokemon`/`getSwitchedPokemon` with `searchid = ident|details` matching plus Illusion fallback in `client/src/battle.ts:263-344`) and mutates `hp/boosts/volatiles/sideConditions/field`. `|request|` is special: `parseRequest` normalizes the JSON then `Battle.update` reconciles authoritative team/PP state (`client/src/battle.ts:106-183`, `protocol/src/index.ts:2138-2197`).
- Flow 2: static data lookup with gen layering + competitive filter (`dex/index.ts:1382-1442` → `data/index.ts:57-130`). `new ModdedDex('gen5')` calls `loadData` per table; each `load` seeds from `DATA[type][gen]` then walks to the parent (`forGen(gen+1)` or `Scripts.inherit`) merging missing keys / `{inherit:true}` partials; `DexTable.get` applies alias + normalization (Hidden Power/Return/Frustration slicing, gen≤3 physical/special recategorization, `Future`/`Illegal` marking) with per-id memo caches. `data.Generations.get(n)` wraps that dex and every accessor (`Abilities.get`, `Species.get`, `Types.get`, …) re-checks the injected `ExistsFn`, with `Specie`/`Type` adapters reshaping abilities/evos tiers and `damageTaken` encoding on the way out.
- Flow 3: teams in/out + choice loop (`sets/src/sets.ts:92-201` ↔ `sets/src/teams.ts:93-125` → `view/src/choices.ts:108-165`). Import/export parses human text or `|`-packed sets (`_import`/`_unpack`) including ability-index (`0/1/H/S`), EVs/IVs, `S` shiny, level/happiness, and trailing `hpType,pokeball,G,dynamax,teraType` misc fields; `Teams.packTeam` joins with `]` for `/utm`. In battle, server `|request|` JSON → `Protocol.parseRequest` → `ChoiceBuilder(request)` pre-fills `pass` for inactive/forced slots, `addChoice('move 2 mega +1')` parses suffixes/target and buffers partial `current` until target known, then `toString()` emits the comma-joined choice string the server consumes.
- Flow 4: log rendering + codegen pipeline (`view/src/formatter.ts:327-363` + `build:61-179`). `LogFormatter.formatText(args,kwArgs)` first runs `sectionBreak` (inserts `\n` on `postMajor/major→major` transitions), then dispatches to the inner `Handler` method that fills `[POKEMON]/[MOVE]/[EFFECT]/[STAT]` placeholders from `text.json` — using the `Tracker` *pre-mutation* snapshot (hence formatter-before-client ordering). Separately, `./import` syncs `vendor/pokemon-showdown*` submodules and regenerates `dex/data/*.json` + `sim/` + `streams/` extractions; `./build` (`tsc` CJS+ESM with `.mjs` relinking, then `tsup` bundle + optional `esbuild` IIFE `window.pkmn.*` min build) publishes each `@pkmn/*` package.

## Patterns & rationale
- Pattern: Branded-type contract-first design (`types` + `protocol` tuple types) — why: Showdown's wire has ~100 message shapes with kwargs; encoding them as `Args`/`KWArgs` unions gives exhaustiveness in `client.Handler` and `view.Handler` and `verifier` without sharing runtime. Trade-off: large type surface to keep in sync with upstream.
- Pattern: Message-dispatch / event-sourced client (`Battle.add` → `Handler[cmd]`) — why: mirrors server log as source of truth; adding a gen mechanic = adding one handler method + volatile key. Trade-off: implicit coupling — method names must match protocol keys; missed keys silently no-op (`Protocol.key` returns `undefined`).
- Pattern: Null-Object + graceful degradation (`NULL` in `client/src/battle.ts:16-199`, `EMPTY_CONDITION` in `dex/index.ts:86`) — why: client often runs with older dex than server; unknown moves/abilities render as inert conditions instead of crashing.
- Pattern: Inheritance-chain data layering (`ModdedDex.load`) + Façade (`data.Generation`) — why: avoids duplicating 9 gens × full data; each gen stores only diffs, parent provides the rest; façade then applies competitive legality filtering separately from raw storage. Trade-off: deep-clone only for `Species`, shared refs otherwise — mutation risk if callers write through.
- Pattern: Snapshot/Tracker interface decoupling `view` from `client` (`view/src/formatter.ts:45-65`) — why: formatter needs pre-update values (damage %, weather, illusion target) that mutation destroys; interface lets any tracker back it. Trade-off: caller must remember formatter-before-handler ordering.
- Pattern: Pure builders for I/O edges (`login` returns `Action`, `protocol` only parses, `ChoiceBuilder` only builds strings) — why: testable without network/DOM; host decides fetch/render. Trade-off: more glue code in consumers.
- Pattern: Code generation over reimplementation for `sim`/`streams`/dex JSON — why: fidelity to Showdown mechanics beats hand-porting; `pkmn/ps` owns only the seams (data API, client mirror, protocol types). Trade-off: `vendor/` emptiness blocks regeneration; `sim` behavior must be debugged upstream.
- Pattern: Data-driven templates (`view/src/data/text.json` + `template(type, …namespaces)` with gen overrides) — why: log phrasing varies per effect/gen without code branches. Trade-off: JSON bloat and indirection when tracing a message.
- Deliberate non-pattern: no ORM/store/framework, no central event bus — state lives in mutable `Battle/Pokemon/Side/Field` graphs mutated in place for speed and to mirror Showdown's own model; `provider` injection in `Side` ctor (`client/src/side.ts:42-47`) and `field/side` factory args in `Battle` ctor (`client/src/battle.ts:59-65`) are the only DI seams.

## Coupling & extension points
- Stable seams to build on: `types` brands + `Protocol` parse/key (`protocol/src/index.ts:1954-2237`) — consume don't fork; `data.Generation(s)` + `Dex.forGen/mod` for versioned lookups; `Battle` ctor `field/side` factories and `Side` `provider` for custom `Pokemon` subclasses; `Tracker` to plug alternate state into `LogFormatter`; `Data` interface in `sets` (`sets/src/sets.ts:20-39`) and `Data` in `view/choices` (`view/src/choices.ts:28-30`) for name resolution without importing `dex`; `TeamGenerators.getTeamGenerator(format, seed)` registry (`randoms/src/index.ts:39-50`) for new formats; per-mod `mods/src/<mod>/*` + `Dex.mod(id, modData)` for format overrides.
- Coupling points / risks: `client` hard-depends on both `data` (for `Generations`) and `protocol` (for `Args/KWArgs`) — protocol drift breaks handlers silently; `Pokemon.types/species/ability` getters re-query `battle.gen` every access (cache misses cost, stale-gen bugs possible); `Side.addPokemon` Illusion/speciesClause dedupe mutates `team` array in place (`client/src/side.ts:142-205`); `Pokemon.rememberMove/useMove` PP merging has gen/champions special cases (`client/src/pokemon.ts:412-547`); `Learnsets.learnable` caches per species but `isLegal` is explicitly teambuilder-only, real legality needs `sim.TeamValidator` (`data/index.ts:578-652`); `Sets.fromJSON/canonicalize` are documented unvalidated/sort-sensitive (`sets/src/sets.ts:346-350`, `sets/src/teams.ts:78-91`); `build` rewrites ESM imports to `.mjs` by filesystem probe — fragile to new entry layouts (`build:81-109`).
