# Architecture Report — engine

## Overview
- `@pkmn/engine` ("minimal, complete Pokémon battle simulation engine optimized for performance", `package.json:2-4`) is a **Zig core + TypeScript driver** split: deterministic, no-alloc battle logic lives in `src/lib/**/*.zig` behind `build.zig`, and ergonomic JS access/serialization/display lives in `src/pkg/**/*.ts` compiled to `build/pkg/` (`package.json:8-9`, `src/lib/pkmn.zig:1-209`, `build.zig:12-263`).
- The governing principle is **"no compromises" on performance** (`docs/DESIGN.md:11-57`): targeted scope (no validation, no streams, no team/format logic), data-oriented `extern struct` layouts, no strings/pointers/dynamic allocation in the hot path, native-endian binary serialization, and per-generation duplication so gen1 never pays for gen2+ complexity.
- Behavior is selected at **compile time via `build_options`** (`src/lib/common/options.zig:1-55`, `build.zig:42-53`): `showdown` (cartridge vs Pokémon Showdown RNG/bugs/clauses), `log` (binary protocol), `chance` (RNG-event probability tracking), `calc` (RNG overrides + damage summaries). `Makefile:11-12` builds both `pkmn` and `pkmn-showdown` variants with `-Dlog -Dchance -Dcalc`.
- Runtime interaction is a tiny surface: `Battle.update(c1,c2,options) -> Result` and `Battle.choices(player,request,out) -> u8` per generation (`src/lib/gen1/data.zig:101-117`, `src/lib/gen2/data.zig:79-80`), exposed verbatim over three FFI targets — C static/dynamic lib (`src/lib/c.zig:1-46`, `src/lib/bindings/c.zig`), Node-API addon (`src/lib/node.zig`, `src/lib/bindings/node.zig:50-117`), and WASM (`src/lib/wasm.zig`, `src/lib/bindings/wasm.zig:9-47`) — with a TS `addon.ts` dispatcher that loads `build/lib/pkmn(.node|.wasm)` (`src/pkg/addon/node.ts:9-13`, `src/pkg/addon.ts:57-74`).
- TS never owns simulation state: `Battle`/`Side`/`Pokemon` in `src/pkg/gen1.ts:26-742` are **zero-copy `DataView` lenses** over the Zig `Battle` byte buffer using generated `LAYOUT` offsets/sizes + `Lookup` ID translation (`src/pkg/data.ts:1-181`). All strings (`@pkmn/data` species/move/type/item IDs) live only on the TS side (`docs/DESIGN.md:46-49`).

## Patterns & rationale
- Pattern: **Compile-time feature injection via `build_options` + Null Object** — `options.{log,chance,calc}` booleans + `gen.NULL` / `protocol.NULL` / `chance.NULL` / `calc.NULL` (`src/lib/gen1/data.zig:41`, `src/lib/common/protocol.zig`, `src/lib/pkmn.zig:33-49`). Why: MCTS playouts that never read logs/probabilities pay zero branches/bytes; trade-off is combinatorial build matrix (`pkmn` × `pkmn-showdown` × flag sets) and TS must probe `options` at load (`src/pkg/addon.ts:40-55`).
- Pattern: **Per-generation silos with shared `common/` only when free** — gen1/gen2 each own `data/mechanics/helpers/chance/calc` (`docs/DESIGN.md:35-40`). Why: cache locality, no cross-gen branching in hot loop, easy reasoning; trade-off is outright duplication (`src/lib/gen2/data.zig:7` imports gen1 only sparingly).
- Pattern: **Caller-allocates, never-allocates core** — `extern struct` battles + fixed `MAX_CHOICES/MAX_LOGS` (`src/lib/gen1/data.zig:19-38`), `out`/`log` buffers allocated once in TS constructor (`src/pkg/gen1.ts:40-42`), `update/choices` take `*Self/[]Choice/*Log` (`src/lib/gen1/data.zig:101-117`). Why: deterministic memory, FFI-friendly POD, suits embedded/WASM; trade-off is manual size bookkeeping and `CHOICES_SIZE` pow2 rounding per `builtin.mode` (`src/lib/gen1/data.zig:29-38`).
- Pattern: **Handles-not-pointers + integer-only IDs** — `Player` enum + packed `ID{id:u3,player}` (`src/lib/common/data.zig:7-46`), `order: [6]u8` indirection instead of pointers (`src/lib/gen1/data.zig:126-150`), Zig enums index directly into data arrays, TS `Lookup` resolves strings outside core (`src/pkg/data.ts:64-181`). Why: avoids hashing/`toID` heat (`docs/DESIGN.md:162-172`), minimizes cache misses; trade-off is all string UX pushed to driver code.
- Pattern: **Synchronous byte-buffer FFI, no streams** — `update` takes two `u8` choices + optional log buffer, returns one `u8` result (`src/lib/bindings/node.zig:50-90`); explicitly rejects Showdown `BattleStream` async-text model (`docs/DESIGN.md:20-28`). Why: minimal syscall/parse overhead for search-heavy workloads; trade-off is no input validation — driver must guarantee legal choices.
- Pattern: **Dual RNG personalities behind one `PRNG(gen)` alias** — cartridge `Gen12` (9-byte LCG, `src/lib/common/rng.zig:81-103`) vs `PSRNG` (Gen5/6-based, `src/lib/common/rng.zig:34-71`) switched by `showdown` (`src/lib/common/rng.zig:8-18`, `docs/DESIGN.md:60-76`). Why: bit-exact parity with either cartridge or Showdown verified by integration fixtures; trade-off is layout divergence (seed bytes vs 64-bit chunks, `src/pkg/gen1.ts:86-106`) and `showdown` baked into artifact name.
- Pattern: **Codegen from `@pkmn/data`/`@pkmn/sim` Dex** — `generate.ts` + Mustache templates as single source of truth for species/moves/types/items. Why: ruthlessly pruned, perfectly-hashed/linear-searchable tables without hand-maintenance; trade-off is generated-file churn and build dependency on npm Dex packages (`package.json:97-107`).

## Coupling & extension points
- **Shared `common/` kernel is the blast radius** — `data.zig` (`Choice/Result/Player/ID` packing), `battle.zig` (`Options` triple), `protocol.zig` (`ArgType`), `rng.zig`, `rational.zig` are imported by every gen (`src/lib/gen1/data.zig:1-13`, `src/lib/gen2/data.zig:1-17`); changing byte layouts there breaks all FFI + TS offsets + fixtures simultaneously.
- **`LAYOUT`/`IDS` JSON is the versioned ABI** — TS views (`src/pkg/gen1.ts`), `Lookup`, protocol parser (`src/pkg/protocol.ts`), debug UI, and `*.bin` fixtures all assume matching `sizes/offsets`; regenerate + rebuild together (`src/tools/generate.ts`, `Makefile:33-35`); `LE` probe (`src/pkg/data.ts:7-11`) + native-endian protocol (`docs/DESIGN.md:41-45`) means buffers are **not portable across endianness**.
- **Adding a generation = clone a `gen*/` silo + extend facade** — new `src/lib/genN/{data,mechanics,helpers,chance,calc}.zig`, export in `src/lib/pkmn.zig:155-200`, add binding slot (`src/lib/bindings/node.zig:30-34` array length, `wasm.zig:9`), extend `IDS/LAYOUT` + `Lookup` (`src/pkg/data.ts:13-36,73-78`) and `Battle.create/restore` switch (`src/pkg/index.ts:343-351`), plus `package.json:52-84` `files` list and `pkmn.h` exports.
- **Adding a build flag = extend `Options` + `build_options`** — add field in `src/lib/common/options.zig:5-17` + `build.zig:49-53` plumbing + `PKMN_OPTIONS` in `src/include/pkmn.h:51-58` and `node.zig:18-28` exposure; TS must thread it through `Bindings.options` (`src/pkg/addon.ts:6-14`) and `check/supports`.
- **Safe extension seams (no core fork needed)** — implement validation/AI/search/drivers on top of `API.update/choices/bytes/toJSON` (`src/pkg/index.ts:23-49`); custom log renderers on raw `log: DataView` + `Info` (`src/pkg/protocol.ts:50-84`); RNG forcing via `Calc.overrides` and probability reads via `Chance`/`Rational` without touching `mechanics`; new tools as `zig build` steps following `tool()` pattern (`build.zig:424-457`) reusing `pkmn` module import.
